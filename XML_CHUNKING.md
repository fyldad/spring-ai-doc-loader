# XML, SOAP, and Maven semantic chunking

Roadmap step 5 is implemented in the existing function pipeline. `documentReader` gathers the admitted files for each subscription before extraction, making imports and Java links independent of scan order. This currently retains decoded sources and parsed XML for the entire run in memory; a disk-backed inventory is future work for very large corpora. Discovery's per-file size and exclusion policies still apply.

```yaml
ingestion:
  xml:
    max-import-depth: 16
    max-import-files: 128 # includes the starting contract
    element-names: [bean, route, endpoint] # generic XML local element names
    maven-resolution-policy: declared # optionally local-properties
```

`XmlSourceReader` uses the namespace-aware secure parser used by discovery. DTDs and external entities are disabled. Its explicit resolver accepts relative WSDL/XSD import/include paths only when the target is already admitted in the same repository's discovery inventory. It never opens another file or fetches a URL. Absolute paths, URLs, excluded/unreadable files, cross-repository targets, incompatible namespaces, and unsupported document kinds remain unresolved with diagnostics. Import depth/file limits bound traversal and revisits terminate cycles. Duplicate QName declarations remain ambiguous. Chameleon includes, schema redefinition semantics, local catalogs, and WSDL 2.0 extraction are unsupported; WSDL 2.0 remains a searchable `wsdl_unsupported` unit.

`LocatedXml` first validates XML securely, then maps DOM elements to lexical offsets in the exact decoded source. Its scanner handles comments, CDATA, processing instructions, quoted `>` characters, and self-closing elements, verifies lexical/DOM agreement, and retains source formatting. It does not derive ranges from serialized DOM. Namespace URIs and expanded QNames drive semantic identity; a prefix change does not change a named declaration's parent ID. Configuration that was redacted during discovery uses the sanitized snapshot and retains `location_basis=sanitized_snapshot`.

WSDL 1.1 emits a compact definitions overview, services and ports, individual portType operations, messages, bindings, documentation/import declarations, and embedded XSD declarations. An operation carries input/output/fault message and part references, bindings, SOAP 1.1/1.2 actions, and service/port facts. Links point to XSD parent IDs, whose document parts retain exact locations. XSD emits global elements, complex/simple types, groups/attributes and other top-level declarations. Its factual context records field qualification, occurrences (including enclosing sequence/choice), attribute use, nillability, base/type references, restrictions, and documentation. Related declarations are linked without recursively copying schema text.

Maven emits an overview, parent/modules/properties blocks, dependency groups and individual dependencies, dependency management, plugins/configuration, repositories, and inactive profiles. `dependency_model=declared` is always explicit. `declared_version` and `version` preserve the lexical version; an absent version is `version_not_declared`, and default dependency scope is `compile`. Parent group/version is not fabricated in extraction from discovery's inherited coordinate hints. BOMs and dependency-management entries are declarations, never automatically applied to dependencies.

The default `declared` policy evaluates no Maven model. `local-properties` can interpolate versions from only this POM's base properties, with bounded expansion and cycle handling. A successful interpolation adds `resolved_version` and `resolution_status=local_properties`; it still does not claim an effective dependency. Profile versions, parent properties, environment/system properties, BOMs, profiles, and external parents remain unresolved. `profile`, `active_profiles`, `maven_resolution_policy`, and placeholder metadata expose the policy and declaration context.

Literal `@WebService`, `@WebMethod`, `@PayloadRoot`, `@XmlRootElement`, and `@XmlType` attributes support repository-local Java/contract matching. `endpointInterface` links implementations to service interfaces. Annotation names are currently recognized lexically, so all Java matches are labelled `inferred`, including matches using explicit namespace/name attributes. Defaults, constants, package-level JAXB namespace defaults, and full annotation/classpath resolution remain future work.

The shared document factory repeats bounded factual headers, splits oversized XML at element/tag boundaries where possible, and falls back to lines/characters for oversized text nodes. `ingestion.chunks.max-characters` includes the header; the default is 1200. Prefix-independent QNames and internal relationships stay complete in metadata/snapshots even when header context is shortened. Long context and relationships live in content-addressed snapshots referenced by `contract_context_snapshot` and `relationships_snapshot`, outside vector payload lists. Original source and parent snapshots provide exact citations; source hashes, offsets and headers retain the existing contract.

Malformed/unsafe XML discovered on disk remains a discovery failure with a CSV record and is not indexed. If an admitted file fails semantic parsing/extraction, it becomes an `xml_fallback` with a diagnostic containing only the exception type. Run `./gradlew.bat test` to verify namespace aliases, imports/cycles/limits, unsafe inputs, request/response/fault links, XSD constraints, Maven policy, Java annotation links, exact ranges, bounded splitting, and the composed pipeline with a mocked vector store. These tests establish extraction correctness; retrieval quality still requires the benchmark from step 1.
